# 도디쌤의 규정줍줍 — 구조 설명서 (v0.5 시제품)

© 김정환 · M.A.D.T (Moral And Digital Teacher)

## 1. 이 프로그램이 하는 일

선생님이 자기 업무의 규정집·길라잡이 PDF를 넣으면, 질문에 들어 있는 낱말로 문서를 찾아
**원문 그대로, 쪽수와 함께** 보여 줍니다. AI를 쓰지 않습니다. 서버도 로그인도 없습니다.

## 1-1. 쓰는 방식: 작업표시줄에 꽂아 두고 꺼내 보기

이 프로그램은 **작업표시줄에 꽂아 두고 쓰는 것이 기본**입니다. 업무 중 한글·나이스를 쓰다가
작업표시줄의 꿈송이 아이콘(이름: 규정줍줍)을 누르면 작은 창으로 바로 꺼내 볼 수 있습니다.
- 설치하기 전에는 화면 위쪽에 노란 📌 버튼이 늘 떠 있습니다. 누르면 설치가 시작됩니다.
- 설치 후 작업표시줄 아이콘을 마우스 오른쪽 단추로 눌러 [작업 표시줄에 고정]을 해 두면 끝입니다.
- 작업표시줄에 보이는 이름은 `manifest.webmanifest`의 `short_name`("규정줍줍")입니다.
- 이름을 바꾸면 **이미 설치한 선생님 컴퓨터에서는 바로 바뀌지 않을 수 있습니다.** 그럴 때는 앱을 지웠다가 다시 설치하면 됩니다.

## 2. 전체 파일 구조

```
gyujeong/                  ← 이 폴더를 통째로 깃허브에 올립니다
├─ index.html              ← 프로그램 전부(화면 + 엔진 + 동작). 고칠 일은 거의 여기뿐
├─ manifest.webmanifest    ← '앱으로 설치'할 때 이름·아이콘·창 모양을 알려 주는 파일
├─ sw.js                   ← 서비스 워커. 인터넷이 끊겨도 화면이 뜨게 해 줌
├─ dodi.jpg                ← 도디쌤 그림(위쪽 제목 띠)
├─ ggumsong.png            ← 꿈송이 그림(설명하는 말풍선 옆, 첫 인사)
├─ icon-192.png            ← 작업표시줄·바탕화면 아이콘(꿈송이)
├─ icon-512.png            ← 큰 아이콘
├─ icon-maskable-512.png   ← 둥근 아이콘용(휴대폰 등)
├─ lib/
│  ├─ pdf.min.js           ← PDF 읽는 부품(pdf.js 3.11.174). 고치지 않음
│  └─ pdf.worker.min.js    ← 위 부품의 짝. 고치지 않음
└─ 구조설명서.md            ← 이 문서
```

## 3. index.html 안의 구역

줄 번호는 고칠 때마다 바뀌므로, 메모장이나 깃허브 편집 화면에서 **Ctrl+F로 아래 낱말을 찾으세요.**

| 찾을 낱말 | 구역 | 하는 일 |
|---|---|---|
| `[화면 꾸밈]` | 화면 꾸밈 | 색·글자 크기. 색은 `:root`의 `--navy`, `--yel`만 바꾸면 전체가 바뀜 |
| `===== 엔진` | 엔진 | 화면과 상관없는 계산 부분 시작 |
| `function splitSheet` | 엔진 | 한 장에 두 쪽이 나란히 인쇄된 PDF를 왼쪽·오른쪽으로 나눔 |
| `function buildPages` | 엔진 | 인쇄된 쪽 번호(- 3 -)를 찾고, 쪽마다 반복되는 머리말·꼬리말을 뺌 |
| `function chunkPages` | 엔진 | 문서를 '부분'으로 자름: 제○조 → 1 / 가. / 1) 제목 → 서식 → 길이 순 |
| `const STOP=` | 엔진 | 질문에서 버리는 말(어떻게, 알려줘…) |
| `const ENDING=`, `const JOSA=` | 엔진 | 떼어 내는 말끝(…인가요)·조사(은·는·이·가) |
| `const INTENTS=` | 엔진 | **질문 종류 판별**(기간·인원·금액·가능 여부·방법·뜻·서식)과 답일 법한 표현 |
| `function queryGroups` | 엔진 | 질문에서 찾을 낱말을 뽑음. 문서에 없는 말은 줄이거나 쪼갬 |
| `function search(` | 엔진 | 낱말이 든 부분을 찾아 점수를 매김 |
| `===== 화면 동작` | 화면 | 말풍선, 버튼, 문서 창, 설정 창 시작 |
| `[자주 고칠 곳 ①]` | 화면 | **기본 동의어 사전** |
| `===== 저장소` | 화면 | 이 컴퓨터 브라우저 안(IndexedDB)에 저장 |
| `===== 질문 → 찾기 → 답` | 화면 | 질문을 받아 결과 카드를 만드는 곳. 안내 문구도 여기 |
| `===== PDF 읽기` | 화면 | PDF에서 글자를 뽑는 곳. 오류 안내 문구도 여기 |
| `===== 문서 묶음` | 화면 | 내보내기·가져오기 |
| `===== 설치` | 화면 | 작업표시줄 설치 안내 문구 |

## 4. 자료 흐름 (교사만 씁니다. 학생용 화면·학생 자료는 없습니다)

```
[교사가 PDF를 끌어다 놓음]
      ↓  (브라우저 안에서만 처리. 어디로도 보내지 않음)
[글자 뽑기] → [쪽 나누기·쪽 번호 찾기] → [부분으로 자르기]
      ↓
[이 컴퓨터 브라우저 안 저장소에 '글자만' 저장]   ※ PDF 원본 파일은 저장하지 않음
      ↓
[질문] → [말끝·조사 떼기] → [동의어 더하기] → [부분마다 점수] → [위에서 3건 보여 주기]
```

- 교사 A의 컴퓨터에 넣은 문서는 교사 B에게 보이지 않습니다. 서로 이어져 있지 않습니다.
- 나누고 싶을 때만 [설정 → 묶음 내보내기]로 만든 `규정묶음_날짜.json` 파일을 직접 건넵니다.
- 인터넷으로 나가는 것: 사이트 파일을 받아 오는 것뿐입니다. 아주 드물게 글자 표(cMap)가 필요한
  PDF를 만나면 pdf.js 공개 저장소(jsdelivr)에서 글자 표 파일만 받아 옵니다. 문서 내용은 보내지 않습니다.

## 5. 질문 분석과 찾는 방식

**질문 분석 (AI 없이 규칙으로)**
1. 질문을 띄어쓰기로 나누고, "어떻게·알려줘" 같은 말을 버리고, "…은/는/이/가", "…인가요/해요"를 뗍니다.
2. **문서에 없는 말은 문서에 맞춰 고칩니다.**
   - 말끝 줄이기: "퇴학시킬" → 문서에 "퇴학"이 있으면 "퇴학"으로.
   - 쪼개기: "출석정지기간"처럼 붙여 쓴 말 → 문서에 있는 "출석정지" + "기간"으로.
3. **질문 종류를 알아봅니다.** "며칠·언제까지"는 기간, "몇 명"은 인원, "얼마"는 금액, "해도 돼?"는 가능 여부,
   "어떻게"는 방법·절차, "뭐야"는 뜻. 종류마다 답일 법한 표현(○일 이내, ○인 이상, ○원, 할 수 있다/없다 …)이
   적힌 부분을 위로 올리고, 화면에서 **초록색**으로 표시합니다.
4. 동의어 사전에 있는 낱말이 질문에 있으면 같은 줄의 낱말도 함께 찾습니다.
5. 질문에 **문서 이름**이 들어 있으면("학폭 길라잡이에서 …") 그 문서를 먼저 보여 줍니다.
6. 답 위에 "찾은 낱말 / 질문 종류"를 적어, 프로그램이 질문을 어떻게 이해했는지 보여 줍니다.

**점수 매기기**
- 문서와 질문 모두 띄어쓰기·가운뎃점을 없앤 글자로 비교합니다("재심의신청" = "재심의 신청").
- 올라가는 경우: 드문 낱말일수록, 제목에 있을수록, 질문 낱말이 여러 개 함께 있을수록, 낱말끼리 가까이 있을수록,
  답일 법한 표현이 낱말 바로 곁에 있을수록.
- 내려가는 경우: 서식(빈 칸 양식) 부분. 단, 질문에 "서식·양식"이 있으면 오히려 올립니다.
- 문서가 여러 개일 때: 처음 3건이 한 문서로만 채워지지 않게 하고, 답 위에 **문서별 단추**(문서 이름 + 건수)를 둡니다.

**못 하는 것 (AI가 아니라서)**
- 낱말이 전혀 다른 질문("폰 걷어도 돼?" ↔ 문서에는 "통신기기 보관") → 동의어 사전에 넣어야 찾습니다.
- 오타("츨석정지"), 여러 조항을 합쳐 판단해야 하는 질문, "그럼 그 다음은?" 같은 이어지는 질문.

## 6. 자주 고칠 곳 (Ctrl+F로 찾기)

| 고치고 싶은 것 | 찾을 낱말 |
|---|---|
| 기본 동의어 | `DEFAULT_SYN`. 한 줄에 한 묶음, 쉼표로 나눔. (각자 화면의 [설정]에서도 고칠 수 있음) |
| 질문 종류·답 표현 추가 | `const INTENTS=`. `q`는 질문에서 찾는 말, `a`는 답일 법한 표현 |
| 질문에서 버릴 말 | `const STOP=` |
| 한 부분의 최대 길이 | `MAXLEN=900` (글자 수). 줄이면 결과가 짧고 정확해지고, 늘리면 앞뒤 맥락이 많아짐 |
| 처음 보여 주는 건수 | `showMore(id,3)`의 3 |
| 색 | `:root` |
| 첫 인사 문구 | `function hello()` |
| 꿈송이가 설명하는 사용법(4단계) | `function guideHTML()`. 질문창에 "사용법"을 쳐도 나옴 |
| 판 번호 | `APP_VER` |

※ 수정해서 다시 올린 뒤 화면이 그대로면 **Ctrl+F5**(강력 새로 고침)를 누르세요.

## 7. 개인정보·오류 위험 지점

| 위험 | 지금 상태 | 할 일 |
|---|---|---|
| 학생 이름이 든 문서를 넣음 | 프로그램이 막지 못함. 안내 문구만 있음 | 선생님들께 "규정·길라잡이만 넣기"를 안내 |
| 묶음 파일(.json)을 공개된 곳에 올림 | 묶음에는 문서 글자가 전부 들어 있음 | 학교 내부 자료 묶음은 필요한 분께만 직접 전달 |
| 교육청 길라잡이 PDF를 깃허브 저장소에 올림 | 저장소가 공개라 누구나 받을 수 있음 | PDF·묶음 파일은 저장소에 올리지 않기 |
| 브라우저 '인터넷 사용 기록 삭제' | 넣은 문서가 모두 지워짐 | 미리 [묶음 내보내기]로 백업 |
| 시크릿 창·카카오톡 화면 | 저장이 안 되거나 설치가 안 됨. 화면 위에 경고가 뜸 | PC 크롬에서 열기 |
| 스캔본 PDF | 글자가 없어 못 읽음. 안내 문구가 뜸 | 원본 한글 파일을 PDF로 다시 저장 |
| 표가 많은 쪽 | 칸 순서가 섞여 보일 수 있음 | 결과의 쪽수를 보고 원문 확인 |
| 낱말이 다르면 못 찾음 | "휴대폰"이라고 물었는데 문서에 "통신기기"뿐이면 못 찾음 | 동의어 사전에 추가 |
| 답을 그대로 믿음 | 찾은 곳이 질문과 다른 내용일 수 있음 | 답마다 "원문을 꼭 확인해 주세요"를 표시함 |

## 8. 시험한 것과 못 한 것 (v0.2)

**시험함** (크롬, 가로 440 창)
- 「학생생활교육위원회 운영 지침」(24장, 한 장에 두 쪽씩 인쇄 → 48쪽): 97개 부분으로 나뉨, 읽는 데 1초 안팎
- 질문 15가지, 문서 켜고 끄기, 지우기, 동의어 저장, 묶음 내보내기·가져오기, 새로 고침 뒤 유지, 한글 파일·깨진 PDF 안내
- **규모 시험**: 위 문서를 8번 이어 붙인 384쪽짜리를 이름만 바꿔 12개(모두 4,608쪽, 7,212개 부분) 넣음
  - 넣기: 12개에 약 28초(파일당 2~3초)
  - 찾기: 질문 하나에 0.02~0.04초
  - 다시 열기: 0.3초
  - 저장 공간: 약 3MB / 묶음 파일: 7.4MB

**아직 못 함**
- 실제 '앱으로 설치' 후 작업표시줄 고정 (선생님 PC에서 직접 확인 필요)
- **서로 다른** 규정집 10개에서의 순위 품질 (규모 시험은 같은 문서를 복사한 것이라 속도만 확인함)
- 제○조로만 된 학교 규정집 여러 개를 한 PDF로 묶은 문서, 표가 대부분인 문서
- 엣지·웨일 브라우저, 학교 업무용 PC(성능이 낮으면 넣는 시간이 더 걸림)

## 9. 깃허브에 올리는 법

1. 받은 `gyujeong.zip`의 압축을 풉니다. `gyujeong` 폴더가 나옵니다.
2. 깃허브에서 `Qdice` 저장소를 엽니다.
3. **Add file → Upload files**를 누릅니다.
4. `gyujeong` **폴더를 통째로** 끌어다 놓습니다. (안의 `lib` 폴더까지 같이 올라갑니다)
5. 아래 **Commit changes**를 누릅니다.
6. 1~2분 뒤 `https://gtk0624-a11y.github.io/Qdice/gyujeong/` 로 접속합니다.
