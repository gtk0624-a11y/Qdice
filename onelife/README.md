## 1. 전체 파일 구조

```
onelife/
├─ index.html    ← 프로그램 본체 (학생 화면 + 교사 화면 + 내용 편집 + 저장 장치)
├─ content.js    ← 단원 내용 (사건·선택지·차시 문항·RAFTS·사상가 카드) ★ 가장 자주 고치는 파일
├─ teacher.html  ← 교사 화면 바로가기 (index.html?mode=teacher 로 이동만 함)
└─ README.md     ← 이 문서
```

- 내용은 **두 곳**에 있습니다.
  1. `content.js`: 처음 만든 **기본 내용**입니다.
  2. 교사 화면의 **✏️ 내용 편집**에서 저장한 **편집본**입니다. Firebase의 `rooms/OLCONTENT/default`에 저장되며, 기본 내용보다 **우선** 적용됩니다.
- 편집본은 모든 반이 함께 씁니다. 1반에서 고치면 같은 교과서를 쓰는 모든 반에 바로 반영됩니다.
- 처음 내용으로 돌아가려면 편집 화면에서 **[처음 내용으로 되돌리기]**를 누릅니다.

## 2. 수업 흐름

1. 교사가 슬라이드·영상으로 개념 수업을 합니다.
2. 학생은 🎬 **인생 사건**에서 선택합니다. 필요하면 교사가 ⏸ **갈림길**로 반 전체를 멈추고 선택 분포를 보며 토론합니다.
3. 학생은 ✏️ **차시 글쓰기**를 합니다. 개념어를 1개 이상, 60자 이상 써야 완료됩니다. 차시 형성평가로 씁니다.
4. 단원이 끝나면 학생이 📝 **단원 글쓰기(RAFTS)**를 제출합니다. 조건은 개념어 2개 이상, 최소 글자 수, 스스로 확인하기 체크입니다.
5. 교사가 📚 **글 모아보기**에서 ZIP으로 내려받아 **하이러닝에 업로드**합니다. 이어서 AI 채점·피드백을 받습니다.
6. 👥 **학생 현황**에서 📤 업로드 완료 표시와 ✅ 통과를 체크하면, 학생 화면에 다음 단원(다음 나이)이 열립니다.
7. 학년 마지막 글쓰기는 다음과 같습니다.
   - 1학년: 「스무 살의 나에게」 편지를 쓰고 **이어하기 코드(6자리)**를 받습니다.
   - 2학년: 그 코드를 넣으면 같은 인물이 스무 살로 이어지며, 마지막에 「묘비명·추도사」를 씁니다.

## 3. 교사·학생 데이터 흐름

```
[학생 태블릿]                                   [Firebase 실시간 DB: rooms/방코드/]
 기기 저장(localStorage) ──1초 뒤 자동 전송──▶  students/s번호   (선택·가치·글 전체)
                          ◀──실시간 수신──────  meta             (학년·반·진도·오늘 차시·관문·갈림길)
                          ◀──실시간 수신──────  pass/s번호       (교사가 준 통과)
                          ◀──실시간 수신──────  upl/s번호        (하이러닝 업로드 표시)
                          ◀──실시간 수신──────  del/s번호        (삭제된 글 → 학생 기기에서도 지움)
                          ◀──실시간 수신──────  kick/s번호, unlock/s번호 (기록 삭제, 기기 잠금 해제)

[교사 화면] ── rooms/방코드 전체를 실시간 수신 ── 위 meta·pass·upl·del을 씀
[공통]      rooms/OLCONTENT/default/units  (편집한 단원 내용)
            rooms/OLCONTENT/default/img    (편집 화면에서 넣은 이미지, 자동 압축)
            rooms/OLSAVE/코드6자리          (1→2학년 이어하기 코드)
```

- 학생 1명 = `s번호` (예: 7번 → `s7`). 실명은 받지 않고, **인생 속 인물 이름**만 받습니다.
- 학생 글은 기기와 서버 두 곳에 저장됩니다. 인터넷이 끊겨도 기기에 남아 있다가 다시 연결되면 전송됩니다.
- 같은 번호로 **다른 기기**에서 들어오면 막힙니다. 이때는 교사 화면의 [기기 잠금 해제]를 누르면 됩니다.
- Firebase는 「국가 만들기」와 같은 프로젝트(`nation-game-cf684`)를 씁니다. 방 코드는 `OL`로 시작하므로 다른 게임과 섞이지 않습니다.

## 4. 자주 고칠 곳 위치

| 고치고 싶은 것 | 가장 쉬운 방법 | 파일로 고칠 때 |
|---|---|---|
| 사건 상황·선택지·결과·이미지 | 교사 화면 ✏️ 내용 편집 | `content.js` 각 단원의 `ev` |
| 차시 글쓰기 문항·필수 개념어 | ✏️ 내용 편집 | `content.js`의 `lessons` |
| RAFTS 과제·조건·최소 글자 수 | ✏️ 내용 편집 | `content.js`의 `rafts` |
| 단원 개념어(채점 기준) | ✏️ 내용 편집 | `content.js`의 `concepts` |
| 학년 마무리 글쓰기 문항 | 파일 | `content.js` 맨 아래 `ENDINGS` |
| 차시 글 최소 글자 수(60자) | 파일 | `index.html`의 `MINI_MIN` |
| 교사 비밀번호(0624) | 파일 | `index.html`의 `TEACHER_PIN` |
| Firebase 연결 | 파일 | `index.html`의 `FIREBASE_CONFIG` |
| 가치 6개(정직·배려…)·출생 카드 | 파일 | `content.js` 맨 위 |

`content.js`를 고칠 때는 따옴표(' ') 안의 글자만 고치세요. 쉼표·괄호를 지우면 화면이 하얗게 나옵니다.

## 5. 개인정보·오류 위험 지점

**개인정보**
- 학생 글이 Firebase에 **임시 보관**됩니다. 🗂️ 보관·삭제에서 학기 종료일을 넣으면, 종료일에서 정한 일수가 지난 뒤 **하이러닝 업로드 완료 표시(📤)가 된 글만** 자동으로 삭제됩니다.
  - 별도 서버가 없어서, 자동 삭제는 예정일 이후 **교사 화면을 처음 여는 순간** 실행됩니다.
  - 삭제 7일 전부터 교사 화면에 경고가 뜹니다.
- 실명을 받지 않습니다. 학생이 글 속에 실명이나 실제 사연을 쓰지 않도록 수업 중에 안내해 주세요.
- Firebase 보안 규칙이 `rooms` 아래를 누구나 읽고 쓰도록 열어 둔 구조입니다(국가 만들기와 동일). 주소와 방 코드를 아는 사람은 기술적으로 데이터에 접근할 수 있습니다. 민감한 내용을 쓰지 않게 하는 것이 가장 확실한 보호입니다.

**오류 위험**
- **선택지 순서를 바꾸거나 지우는 편집**은 학생들이 이미 고른 뒤라면 기록이 엉킵니다. 편집 화면에 "이미 ○명 선택" 경고가 뜹니다. 문구 다듬기는 괜찮습니다.
- 카카오톡 안에서 열면 **[파일로 저장]**이 안 될 수 있습니다. 이때는 **[복사하기]**를 쓰면 됩니다.
- 학교 와이파이가 Firebase를 막으면 화면 위에 "체험 모드"가 뜹니다. 이 상태에서는 연동이 되지 않으므로 수업 전에 한 번 확인하세요.
- 이미지는 1000px·약 200KB로 자동 압축되어 데이터베이스에 저장됩니다. 학생은 해당 화면을 열 때만 이미지를 불러옵니다. 그래도 단원마다 이미지를 여러 장 넣으면 무료 사용량(월 10GB 전송)에 가까워질 수 있습니다.
- 이미지 저작권은 교사가 확인해야 합니다.
- **방 초기화**는 되돌릴 수 없습니다. "초기화"를 직접 입력해야 실행됩니다.

## 6. 테스트 방법 (연동 없이)

주소 끝에 `&demo=1`을 붙이면 Firebase 없이 이 브라우저 안에서만 저장되는 체험 모드로 열립니다. 같은 브라우저에서 교사 탭과 학생 탭을 동시에 열어 흐름을 미리 볼 수 있습니다.
